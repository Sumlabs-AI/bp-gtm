# Database & Migrations

Postgres 17 + PostGIS ([ADR 0001](../docs/adr/0001-postgis.md); image built from `docker/db/Dockerfile`), SQLAlchemy 2.0 models, Alembic migrations in `apps/api/alembic/versions/`.

## Rules

- **Never** change the schema by hand or with `Base.metadata.create_all`. Every schema change is an Alembic migration.
- **Never** edit a migration that has been merged/applied elsewhere. Write a new one.
- Always **read and fix** autogenerated migrations before committing. Autogenerate misses or mangles: renames (shows as drop + add — data loss!), enum changes, server defaults, data migrations.
- Every migration needs a working `downgrade()`.
- Use `DateTime(timezone=True)` for timestamps.
- Constraint names come from the naming convention in `app/db.py`; don't hand-name them.

## Workflow

From `apps/api`, with the DB running (`docker compose up -d db`):

```bash
# 1. Edit/add models in app/models/ (and export new ones in app/models/__init__.py)
uv run alembic revision --autogenerate -m "add foo table"
# 2. Review the generated file in alembic/versions/
uv run alembic upgrade head
uv run alembic downgrade -1 && uv run alembic upgrade head   # verify downgrade works
uv run alembic check          # confirms models and migrations are in sync
```

Or via Docker from the repo root: `pnpm db:revision "add foo table"` and `pnpm db:migrate`.

The `api` container runs `alembic upgrade head` on start.

## Useful commands

```bash
uv run alembic current        # current revision in the DB
uv run alembic history        # list migrations
docker compose exec db psql -U app -d app   # SQL shell
```

## How it's wired

`alembic/env.py` reads `DATABASE_URL` from `app.config.settings` (not from `alembic.ini`) and uses `Base.metadata` from `app.db`, after importing `app.models` so every model is registered. `compare_type=True` is on so column type changes are detected. The geoalchemy2 Alembic helpers are registered too: autogenerate renders `Geometry` columns and their GIST indexes, and ignores PostGIS's own tables (`spatial_ref_sys`). The first spatial migration (`create cells`) runs `CREATE EXTENSION IF NOT EXISTS postgis`.

Switching an existing volume from the old `postgres:17-alpine` image: dump and restore, see [need-engine.md](need-engine.md#switching-an-existing-database-to-postgis).
